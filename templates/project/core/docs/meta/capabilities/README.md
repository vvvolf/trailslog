# Карточки возможностей

Карточка возможности — короткий живой контракт: когда действие нужно,
какие входы, какую команду вызвать, что она меняет и где подтверждение.

Карточка **не является KA** и не заменяет подробный сценарий. KA — след
понимания; карточка — операционное описание, которое обновляется вместе с
командой.

## Формат

Карточка — Markdown с YAML frontmatter. Обязательные поля:

- `id` — стабильный идентификатор, например `project.create`;
- `title` — человеческое название;
- `kind: capability`;
- `schema: 1`;
- `command` — команда или шаблон команды;
- `readonly` — `true` или `false`;
- `confirm` — нужно ли подтверждение человека;
- `requires` — обязательные аргументы.

Дополнительно:

- `plan` — команда пробного запуска;
- `examples` — короткие примеры;
- `related` — ссылки на runbook, KA, README.

В теле: «Когда использовать», «Входы», «Выходы», «Ограничения», «Пример».

## Правила

- карточка остаётся короткой; подробный алгоритм — в скрипте или runbook;
- сложный сценарий не исполняется моделью по шагам;
- для записи сначала план/пробный запуск, затем подтверждение, затем
  выполнение;
- файлы, начинающиеся с `_`, — шаблоны и не индексируются;
- источник истины — карточка; индекс возможностей — производные данные.
