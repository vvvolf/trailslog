## Совместная работа

- правку сначала показывать в чате, выполнять после явного одобрения;
- коммит — по явной команде, один коммит — одна тема; без `git add -A` /
  `git add .`; `git push` запрещён;
- коммит фиксирует одну законченную единицу понимания: её документы — этим
  коммитом, чужие единицы — другими;
- KA — read-only след происхождения, не живой документ; новое понимание —
  новый KA с переходом «было → стало»; актуальное знание — живой документ
  без пометки KA;
- каждое завершённое изменение (исправление, контракт, решение) получает
  KA; лог или коммит не заменяют KA;
- в KA заполняются `composed_by`, `lead`, `human_participation`,
  `participation_updated`; агент по умолчанию ставит `composed_by: agent`,
  `lead: agent`, `human_participation: none`; человеческое участие
  выставляет человек;
- утверждения о состоянии — со ссылкой на источник или пометкой
  `[не проверено]`; в конце оценки — раздел «что я не проверял».

## Возможности и сложные действия

- карточки возможностей — в `docs/meta/capabilities/`;
- карточка — живой операционный контракт, не KA; она описывает, когда и
  какую команду вызвать;
- сложный сценарий исполняет команда или скрипт, а не модель по шагам;
- для действий записи: сначала пробный запуск или план, затем
  подтверждение человека, затем выполнение;
- модель выбирает только известную возможность и аргументы; произвольный
  shell и обход allowlist запрещены.

## Методика

Слои следуют TrailsLog: живые знания, KA, производные артефакты, журнал,
следы Work Item. Полная методика — в репозитории TrailsLog рабочего
окружения; этот проект хранит только свои правила.

## Private layer

- private log: `docs/tracks/private/log/`;
- private pipeline, WI, tracks и материалы: `docs/tracks/private/`;
- public log: `docs/log/`; не смешивать с private;
- private track не является публичной частью проекта и не заменяет KA;
- public→private ссылки запрещены; private→public допустимы.
