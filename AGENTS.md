# AGENTS.md

Инструкции для ИИ-ассистентов этого репозитория.
О проекте и карте документации — README.md; здесь только специфика агентов.

## Правила совместной работы

- правку сначала показывать в чате, выполнять после явного одобрения;
- коммит — по явной команде, один коммит — одна тема; без `git add -A` /
  `git add .`; `git push` запрещён;
- коммит фиксирует одну законченную единицу понимания: её документы — этим
  коммитом, чужие единицы — другими (см.
  `docs/meta/knowledge/2026-07-16_5-git-as-knowledge-history.md`);
- KA — read-only след происхождения, не живой документ; новое понимание —
  новый KA с переходом «было → стало»; актуальное знание — живой документ
  без пометки KA; превращение ошибочно классифицированного KA в живой
  документ допустимо с новым KA и сохранением истории в Git; ошибочную
  правку неопубликованного KA исправлять в истории (amend/rebase), а не
  корректирующим коммитом;
- отсылки между KA (ссылки «продолжение/предыдущее», `related`) —
  метаданные; их можно добавлять без нового KA, не меняя содержание;
- в KA заполняются метаданные участия: `composed_by`, `lead`,
  `human_participation`, `participation_updated`; словарь и правила —
  `docs/meta/knowledge/2026-10-26_1-KA-participation-authorship-and-lead.md`;
- агент по умолчанию ставит `composed_by: agent`, `lead: agent`,
  `human_participation: none`; он не выставляет человеческое участие;
- человек сам обновляет `human_participation` (`skim`, `line`, `author`)
  и при необходимости `lead: human`; это метаданные, тело KA не меняется;
- модель ролей KA/живых документов —
  `docs/meta/knowledge/2026-10-19_6-knowledge-acquisition-as-read-only-trail.md`;
- KA не содержит приватных имён, путей и размеров; приватные наблюдения
  ведутся в private log приватного track (`docs/tracks/private/log/`), а KA
  формулирует только обобщённое понимание. Приватный конвейер —
  `docs/tracks/private/`. WI и Trail могут быть приватными и наследуют слой
  источника. Публичный KA не ссылается на private log; private log может
  ссылаться на публичный KA. Политика —
  `docs/meta/artefacts/private-log-policy.md`;
- утверждения о состоянии — со ссылкой на источник или пометкой
  [не проверено]; в конце оценки — раздел «что я не проверял»;
- на многослойное сообщение — сначала карта нитей;
- сначала диагностика, потом предложения.

## Безопасная обработка данных

- чувствительные данные не отправлять во внешние сервисы без явного
  разрешения человека;
- локальный этап: локальная модель → черновики WI вне git → человек
  проверяет и редактирует; только после явного «продолжаем» облачная
  модель видит очищенный артефакт;
- телеметрия — счётчики и статусы, не содержимое; не читать
  чувствительный корпус в чате, если человек не разрешил;
- эскалация к платной модели — только по запросу человека, с
  минимально необходимым фрагментом;
- типовой сценарий и границы —
  `docs/meta/knowledge/2026-10-23_1-KA-safe-local-first-data-processing.md`.

## Инструменты

- `tools/` — маленькие self-contained reference-инструменты, которые входят
  в onboarding методики и не имеют отдельного релизного цикла;
- инструмент может жить здесь, если он маленький, без зависимостей и с
  README-контрактом; когда появляются тесты, зависимости, несколько
  потребителей или свой релизный ритм — выносить в отдельный репозиторий;
- `tools/handoff-to-owner/` — передача владения папкой/репозиторием,
  созданными агентом; использовать с явными `--owner` и `--agent`, без имён
  по умолчанию;
- основной режим — reusable: `--target <dir>`; ничего не копируется и не
  удаляется; one-shot копия — только для переносимой папки, тогда имя
  добавляется в локальный `.git/info/exclude` (не `.gitignore`), а скрипт
  удаляет себя после успеха;
- предыдущий KA —
  `docs/meta/knowledge/2026-10-25_1-KA-agent-created-repo-handoff.md`;
- переход и обоснование —
  `docs/meta/knowledge/2026-10-25_3-KA-handoff-reusable-mode-and-acl-order.md`;
- практическая инструкция —
  `tools/handoff-to-owner/README.md`.

## Передача результатов на ревизию

- результат многошаговой работы агент сохраняет в файле задачи
  развёрнуто и помечает блоком «на ревизию»:
  - `performed_by` — модель-исполнитель и дата;
  - `review_recommended` — да/нет;
  - `review_candidates` — модели с ценами (вход/выход за 1М токенов, из
    каталога провайдера) и чем каждая полезна именно этой задаче; одна
    помечается рекомендованной;
- если задача объективно сложнее уровня исполнителя — агент признаёт
  это явно (`review_recommended: yes`) и перечисляет, что именно не
  смог проверить; кандидаты — человек и модели уровнем не ниже
  исполнителя;
- агент ревью-модели сам не запускает: выбор и запуск — решение
  человека; ревьюер дописывает результат в тот же файл (раздел
  «Ревизия»);
- механические задачи (пути, опечатки, переименования) — блок не
  нужен.

## Состояние задач

- `docs/next-tasks.md` — локальный список актуальных задач (вне git); может
  отсутствовать. Если файл есть: поддерживай актуальность по ходу работы
  (устоявшиеся изменения — сразу, с отметкой в чате); у каждой позиции должен
  быть источник в конвейере (`docs/tracks/ideas/work_items/`,
  `docs/meta/work_items/`) — фиксируя задачу, сразу сохраняй её туда.
- черновики WI — вне git (`docs/tracks/ideas/work_items/`,
  `docs/meta/work_items/`), следы — в git (`docs/meta/work_item_trails/`);
  WI живёт в одном месте — после фиксации следа черновик удаляется;
  полнота следа и размещение — в
  `docs/meta/work_item_trails/meta/readme.md`;
- `docs/meta/work_item_trails/README.md` — документация хранилища trail,
  не Work Item.

## План сессии

- `docs/session.md` — локальный (вне git) файл планов сессий. Каждая сессия
  ведёт свою секцию: нити, предложения, решения, открытые вопросы; изменяет
  только свою секцию, правки отмечает строкой в чате. Записи секции самодостаточны — понятны без
  переписки. Не хранилище: значимое промотируется в конвейер и документы.

Шаблон секции:

    ## <session> — active | closed | frozen
    owner: <модель/инструмент>
    opened: <дата время>
    updated: <дата время>

Протокол:

- при начале работы сессия заводит свою секцию и генерирует `session`
  (длинный случайный id);
- сессия изменяет только свою секцию; чужие секции не трогает;
- свою секцию сессия закрывает (`closed`) в конце работы;
- при открытии сессии чужие незакрытые секции — спросить человека:
  «сохранить в конвейеры / удалить / не трогать»; «не трогать» ставит
  `frozen` и снимается только решением человека.
