# Минимальная модель жизненного цикла Work Item

В ходе обсуждения произошло уточнение роли Work Item в архитектуре TrailsLog.

Ранее Work Item рассматривался преимущественно как самостоятельная единица дальнейшей работы.

В результате обсуждения сформировалось понимание, что Work Item также должен обладать собственным жизненным циклом, отражающим его отношение к развитию Meta.

При этом было принято решение не проектировать полный workflow заранее.

Напротив, минимальная модель должна развиваться постепенно по мере накопления практики.

Первым шагом становится введение двух новых обязательных метаданных:

- `category`
- `status`

На текущем этапе предполагается использовать единственную категорию

```yaml
category: Inbox
```

Она означает не место хранения документа, а факт того, что новая единица изменения понимания была захвачена системой и ожидает дальнейшей обработки.

Одновременно сформирована первая версия модели состояний Work Item.

```yaml
status: captured
status: meta_integrated_partially
status: meta_integrated
```

При этом было уточнено важное архитектурное различие.

Статусы описывают не процесс выполнения работы человеком.

Они описывают отношение Work Item к модели знаний Meta.

Это означает:

- `captured` — изменение понимания обнаружено и сохранено;
- `meta_integrated_partially` — часть результатов уже отражена в Meta, однако Work Item продолжает содержать ещё не интегрированное понимание;
- `meta_integrated` — результаты Work Item полностью отражены в Meta, после чего Work Item остаётся частью истории исследования, но перестаёт быть источником необработанного знания.

Таким образом Work Item получает собственную минимальную модель сопровождения, независимую от внутренней структуры Meta.

При этом сознательно принято решение не фиксировать дальнейший workflow.

Появление дополнительных категорий, состояний и правил сопровождения должно происходить только после накопления практики.

## Изменение модели

### Краткое описание изменения модели

Модель знаний дополнена новым понятием — жизненным циклом Work Item.

Work Item перестаёт рассматриваться исключительно как документ фиксации дальнейшей работы и получает собственные метаданные сопровождения.

В модель вводятся обязательные поля `category` и `status`.

При этом статус определяется не степенью выполнения работы, а отношением Work Item к интеграции результатов исследования в Meta.

Одновременно появляется принцип постепенного развития workflow: минимальная модель фиксируется сейчас, полный workflow сознательно откладывается до накопления практики.

---

### Эксперимент 1. Когнитивные операции

Основные мыслительные преобразования, приведшие к изменению модели:

- **Separate** — отделена модель сопровождения Work Item от модели знаний Meta.
- **Reframe** — статусы переосмыслены как описание отношения Work Item к Meta, а не как стадии выполнения задачи.
- **Generalize** — отдельные наблюдения о процессе обработки Work Item обобщены до минимальной модели жизненного цикла.
- **Recognize recurrence** — замечено, что подобные переходы будут повторяться для любого Work Item, что делает оправданным введение единых метаданных.

---

### Эксперимент 2. Структурные изменения модели

В структуру модели добавлены новые элементы:

- обязательное поле `category`;
- обязательное поле `status`;
- понятие минимального жизненного цикла Work Item;
- связь между состояниями Work Item и процессом интеграции знаний в Meta.

Также введён новый архитектурный принцип:

> Workflow Work Item развивается эволюционно и не должен проектироваться полностью до появления практического опыта.

---

### Дополнительная информация для обновления Meta

При обновлении документации Meta следует учитывать следующие изменения.

Необходимо дополнить описание формата Work Item обязательными метаданными:

```yaml
category: Inbox
status: captured
```

Следует явно зафиксировать семантику состояний:

- `captured`;
- `meta_integrated_partially`;
- `meta_integrated`.

Важно отдельно указать, что данные состояния описывают отношение Work Item к модели знаний Meta, а не степень завершённости работы.

Следует также отразить принцип минимального workflow: существующие категории и статусы являются первой итерацией модели и не рассматриваются как окончательный словарь. Предполагается последующее расширение по мере накопления практики без нарушения уже сформированной семантики.
