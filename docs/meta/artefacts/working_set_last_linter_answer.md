Есть ли сведения, отсутствующие в Working Set, но необходимые для сохранения того же понимания проекта, которое даёт Meta?

Да.

* Зафиксирован принцип использования Git как механизма сопровождения истории знаний: Git используется совместно с документами `Knowledge acquisition`. Если происхождение знания естественно восстанавливается по истории изменений, Git достаточен; если нет — происхождение оформляется отдельным документом.

* Зафиксировано понятие **самостоятельной единицы понимания** как минимального объекта сопровождения. Требование смысловой целостности относится именно к истории формирования такой единицы, а не к документам или коммитам самим по себе.

* Зафиксированы роли коммитов и документов `Knowledge acquisition`:

  * коммит фиксирует момент появления одной законченной единицы исследования;
  * документ `Knowledge acquisition` сопровождает внутреннюю историю формирования этой единицы;
  * они выполняют разные функции и не обязаны соответствовать друг другу один к одному.

* Зафиксирован принцип, что история формирования одной самостоятельной единицы понимания не должна искусственно разрываться между несколькими независимыми коммитами или несколькими документами `Knowledge acquisition`.

* Зафиксирован принцип минимизации стоимости сопровождения исследования: документы `Knowledge acquisition` рекомендуется делать небольшими и посвящёнными одной самостоятельной единице исследования, тогда как документы, описывающие сформировавшуюся систему знаний, могут агрегировать множество таких единиц.

* Зафиксировано, что описанный подход к использованию Git и сопровождению знаний рассматривается как **рабочая гипотеза**, требующая проверки практикой.

Противоречий между Working Set и текущим состоянием Meta не обнаружено.
