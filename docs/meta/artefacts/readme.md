# Артефакты Meta: производные документы и их сопровождение

Данный каталог содержит производные артефакты Meta и инфраструктуру их
сопровождения.

- **Производные документы** — собранные из базы знаний
  (`docs/meta/knowledge/`) для удобства использования: Working Set,
  глоссарий. Они не являются источниками истины: источник истины —
  документы knowledge; производные обновляются вслед за ними.
- **Инфраструктура сопровождения** — промпты генераторов и линтеров
  (Working Set, глоссарий, Knowledge acquisition) и вспомогательные
  файлы (результат линтера).

Промпты хранятся рядом с документом, который обслуживают; прецедент —
[`../work_item_trails/meta/`](../work_item_trails/meta/readme.md): спека
Work Item и промпт генерации WI лежат вместе.

Этот readme — индекс каталога: описывает все файлы и даёт прямые ссылки.

## Состав

### working_set.md

Снимок проекта (состояние на июль 2026) — дайджест для диалога с ИИ без
доступа к репозиторию; обновление отложено (см.
`../../tracks/ideas/work_items/2026-10-18-refresh-working-set.md`).

При доступе к файлам источниками служат сами документы; этот файл в таком
режиме не читается (см. `../../../AGENTS.md`).

### working_set_last_linter_answer.md

Последний результат работы линтера.

Документ предназначен для ручного применения изменений к `working_set.md`.

После внесения изменений может быть заменён новым результатом линтера.

### prompt_working_set_generator_gpt.md

Промпт генератора Working Set.

Используется для построения Working Set на основе документов Meta.

### prompt_working_set_linter_gpt.md

Промпт линтера Working Set.

Используется для сопровождения существующей версии Working Set.

Линтер анализирует изменения документации Meta и формирует минимальный
Markdown-патч, необходимый для актуализации `working_set.md`.

### prompt_knowledge_acquisition_generator_gpt.md

Промпт генератора документов `Knowledge acquisition` из обсуждений.

Не относится к сопровождению Working Set. Использовался для формирования
текущего корпуса документов KA в `docs/meta/knowledge/`. Полное описание
будет дописано при возвращении к теме генераторов.

### glossary.md

[Производный глоссарий терминов](glossary.md) методологии: определения
терминов с источниками и пометками готовности
(устойчивый/рабочий/кандидат/вопрос). Не источник истины; актуализируется
вслед за изменениями документов knowledge по промпту ниже.

### Промпт актуализации глоссария (встроен в этот readme)

Задача: привести `glossary.md` в соответствие документам knowledge.

Вход: изменённые и новые документы knowledge (или вся база при первом
прогоне) и текущий `glossary.md`.

Правила:

1. Термины добавляются только при наличии источника в knowledge — со
   ссылкой на документ.
2. У каждого термина: определение «как используется сейчас», источники,
   пометка готовности (устойчивый/рабочий/кандидат/вопрос).
3. Открытые вопросы и расхождения трактовок — пометкой [вопрос], без
   самостоятельных решений.
4. Изменения вносятся только вслед за изменениями источников; своих
   формулировок не добавлять.
5. Если изменений не требуется — вывести ровно «Изменений нет».
6. Выводить только изменённые записи; неизменённые не повторять.

Промпт генерации Work Item и спецификация формата WI живут в каталоге

## Общий принцип

Рабочим документом является только `working_set.md`; `glossary.md` —
рабочий справочник терминов. Остальные файлы представляют собой
инфраструктуру сопровождения производных документов Meta.

Производный документ без механизма обновления дрейфует относительно
источников: WS и глоссарий имеют промпты сопровождения; если появится
новый производный документ — вместе с ним фиксируется способ его
актуализации.
