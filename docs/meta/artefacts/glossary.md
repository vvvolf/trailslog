# Глоссарий терминов (рабочий)

Category: Reference

**Производный документ.** Источник истины — документы knowledge (ссылки —
в каждой записи). Не источник истины сам по себе; актуализируется вслед
за изменениями источников (промпт актуализации — в readme.md этого
каталога). Навигация: ссылка из readme.md этого каталога.

Единое место определений терминов методологии. Ведётся «по готовности»:
у каждого термина — пометка готовности и открытые вопросы. Источники —
документы knowledge, отмечены в каждой записи.

Пометки: **[устойчивый]** — зафиксирован и используется; **[рабочий]** —
используется, но определение не строгое; **[кандидат]** — обсуждался,
не закреплён; **[вопрос]** — термин требует решения.

## Знание и его происхождение

- **Знание** [устойчивый] — «что известно»; самостоятельное утверждение,
  пригодное к переиспользованию независимо от истории появления.
  Источник: `2026-07-16_2-knowledge-and-knowledge-origin.md`.
- **Знание о происхождении знания** [устойчивый] — «как стало известно»:
  постановка вопроса, альтернативы, гипотезы, причины отказов.
  Источник: там же.
- **Knowledge acquisition (KA)** [рабочий] — документ, сопровождающий одну
  самостоятельную единицу исследования; по промпту генератора —
  «контракт изменения модели знаний», category из {Experiment,
  Observation, Principle, Hypothesis}. Вопрос: двойная роль (контейнер
  «исследование + кристалл» против «документ только о происхождении») —
  решается моделью «KA — неизменяемый след; документы знаний — живые»
  (сессия 2026-10-19).
- **Кристалл знания** [кандидат] — небольшой результат итерации
  исследования внутри KA (июль-17).
- **Событие понимания / момент возникновения понимания** [кандидат] —
  момент, когда между уже известными частями обнаруживается новая связь
  (`2026-07-18_4`; обсуждение 2026-07-17).

## Единицы и их объекты

- **Единица понимания** [устойчивый] — объект сопровождения: минимальная
  часть, которую нельзя разделить без потери смысла; её история не должна
  разрываться между коммитами и документами
  (`2026-07-18_1-KA-boundaries-of-knowledge-units`,
  `2026-07-16_5-git-as-knowledge-history`).
- **Изменение понимания** [рабочий] — минимальная смыслово целостная
  единица, к которой предполагается вернуться; объект Work Item
  (`2026-07-21`, спека WI). Вопрос: точное соотношение с «единицей
  понимания» и «единицей исследования».
- **Единица исследования** [рабочий] — то, что сопровождает KA; на вопрос
  «какую единицу исследования сопровождает документ» отвечает
  `scope_of_understanding`. Вопрос: три близких имени сосуществуют без
  явного разведения — нужен осознанный выбор или явное различие.

## Конвейер

- **Work Item (WI)** [устойчивый] — самостоятельная единица дальнейшей
  работы; Markdown с YAML-метаданными (work_item_scope,
  reason_for_capture, resume_context) и сопровождением (category,
  status). Спека: `docs/meta/work_item_trails/meta/spec_work_item.md`.
- **Trail** [устойчивый] — отражение WI для истории, сохраняемое после
  того, как WI изменён или исчез.
- **status (WI)** [рабочий] — отношение WI к интеграции в Meta:
  captured / meta_integrated_partially / meta_integrated; не про
  выполнение работы человеком.
- **reason_for_capture** [рабочий] — почему материал следует сохранить
  как WI (ценность захвата; не происхождение, не план дальнейшей
  работы). Вопрос: кандидаты на отделение (expected_extraction и др.),
  июльское обсуждение не завершено (`2026-07-20-work-Item-metadata-semantics.md`).
- **resume_context** [рабочий] — что нужно знать, чтобы продолжить
  работу без повторного чтения.
- **Руда / файлопомойка** [рабочий] — необработанный материал (заметки,
  диалоги, архивы, файлы), из которого извлекаются знания; «файлопомойка» —
  образ для пользовательской стороны.
- **Захват** [устойчивый] — дешёвая фиксация наблюдения, задачи,
  материала; попасть в очередь должно быть дешевле, чем оформить
  (`2026-07-14_2-capture-principles`, `2026-10-19_1-KA-next-tasks`,
  log `2026-10-17-importance-of-capture`).
- **Механизм vs экземпляр** [кандидат] — предложенный критерий
  переносимости: переносимы описания механизмов, не экземпляры; тест —
  «перенос без замены содержания». Сессия 2026-10-19; подробнее — в
  черновике карты разделения meta.

## Meta и производные представления

- **Meta (понятие)** [устойчивый] — слой хранения знаний о способах
  организации знаний и сопровождения их появления; «память проекта», не
  журнал событий (`2026-07-14_3-why-recording-needs-rules`,
  `2026-07-14_4-what-belongs-in-meta`). Вопрос: отличать от папки
  `docs/meta` (экземпляр).
- **docs/meta (папка)** [рабочий] — экземпляр Meta проекта trailslog.
  Вопрос: граница «технология/контент» внутри неё не проведена (карта
  разделения).
- **Growing Context (растущий контекст)** [рабочий] — гипотеза: контекст —
  среда формирования знаний; новые знания возникают из новых связей
  между известным, а не из новой информации (`2026-07-18_5`).
- **Working Set** [устойчивый] — производный снимок состояния проекта для
  диалога с ИИ без доступа к репозиторию; не источник истины
  (`docs/meta/artefacts/readme.md`).
- **Производные представления** [рабочий] — документы для удобства
  использования (Working Set, потенциально индекс знаний, FAQ);
  источником истины не являются. Вопрос: какие действительно нужны.
- **scope_of_understanding** [устойчивый] — поле KA: какую единицу
  исследования сопровождает документ; источник для автоматической карты
  исследования (`2026-07-18_7-KA-origin-of-scope-of-understanding`).
  Вопрос: узость слова «understanding» (июльское обсуждение).

## Рабочий процесс

- **Коммит** [устойчивый] — фиксация появления одной законченной единицы
  понимания (`2026-07-16_5-git-as-knowledge-history`).
- **Связанные коммиты** [рабочий] — единица понимания, затрагивающая
  несколько репозиториев, фиксируется коммитами с одинаковым сообщением
  (`2026-10-19_3-KA-related-commits`).
- **Слои документации** [рабочий] — общий слой (README: карта, для людей
  и агентов) и агентский слой (AGENTS.md: правила работы агента)
  (`2026-10-18_2-KA-documentation-layers`).
- **Сессия** [рабочий] — единица работы ассистента с длинным случайным id
  и секцией плана в `docs/session.md` (`2026-10-19_2-KA-session-plan`).
- **next-tasks** [рабочий] — локальный список следующих задач: дешёвый
  захват, формализация позже, инвариант источника
  (`2026-10-19_1-KA-next-tasks`).
- **Журнал (log)** [устойчивый] — записи курса проекта, масштаб
  глобальный (`docs/log/meta/2026-10-17-why-log.md`).

## Статус документа

Рабочий глоссарий; пополняется по мере уточнения терминов. Правки
вносятся по мере готовности решений; спорные имена — с пометкой [вопрос].
