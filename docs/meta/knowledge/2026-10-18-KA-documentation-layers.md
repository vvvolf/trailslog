# Документация для людей и инструкции для агентов

## Исходная ситуация

Ориентация и правила оказались перемешаны: часть общих сведений жила
в агентских инструкциях, часть правил — внутри одной из команд ассистента,
а агенту, впервые открывшему проект, приходилось разбирать структуру
перебором. Ни человек, ни агент не получали карту проекта одним чтением.

## Приобретённое понимание

Документация делится по читателю.

README — общий слой: карта репозитория, структура, статусы документов,
точки входа. Нужен и людям, и агентам; поэтому живёт в README, а не
в агентском файле — то, что нужно обоим, не дублируется.

AGENTS.md — агентский слой: только то, что неактуально людям — правила
совместной работы с ассистентом и особенности чтения документов (какие
файлы не читать и почему).

Следствия:

1. Файлы инструкций самодостаточны: каждый рассчитан на чтение отдельно
   от остальных и несёт всё нужное сам.
2. Ссылки на файлы ведут только внутрь этого репозитория: если документ
   ссылается на другой файл — источник, продолжение, пояснение — тот лежит
   здесь же. Веб-ссылки наружу допустимы: правило касается именно файлов.
3. Правила живут там, где агент читает их всегда, — в файле инструкций,
   а не внутри отдельной команды.
4. Инструменты подхватывают файл инструкций автоматически; карта чтения
   остаётся в README, потому что нужна и людям.

## Изменение модели

В модель добавлено различение двух слоёв документации по читателю —
общего и агентского — и правило размещения: общее в README, агентское
в AGENTS.md, без дублирования. Ранее ориентация и правила были смешаны.

## Замечания генерации

Различение сформулировано и сразу применено в проекте; практика пока
короткая. Проверится: удержатся ли правила в агентском файле без дрейфа;
достаточно ли README как единственной карты для людей и агентов.
