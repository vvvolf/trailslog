# Handoff: reusable-режим и ACL до смены владельца

## Исходная ситуация

KA [2026-10-25_1-KA-agent-created-repo-handoff.md](2026-10-25_1-KA-agent-created-repo-handoff.md)
зафиксировал первый контракт: one-shot копия скрипта в целевую папку как
основной сценарий, локальный exclude и самоудаление; reusable-режим был
альтернативой. Практика показала два слабых места.

Во-первых, one-shot копия требует ручной правки `.git/info/exclude` и
оставляет временный файл, если её запустить с `--target`. Во-вторых,
команды из первого KA делали `chown` до `setfacl`: если ACL не
применялся, агент терял доступ. Кроме того, `setfacl` от человека не
работает, пока файлы принадлежат агенту; нужен root.

## Приобретённое понимание

1. **Reusable — основной режим.** Один запуск канонического инструмента с
   `--target` не копирует файлы, не правит exclude и не удаляет себя.
   One-shot остаётся только для папки, которая уезжает из workspace.
2. **ACL до `chown`.** Сначала агент получает ACL; если ACL не
   поддерживается, владение не меняется, и агент не теряет доступ.
3. **Default ACL для обоих.** Новые файлы должны быть доступны и человеку,
   и агенту; default ACL только для агента недостаточно.
4. **`safe.directory` — агенту.** После `chown` владелец — человек;
   агенту нужно исключение, иначе git ругается `dubious ownership`.
   Человеку исключение не нужно.
5. **Локальная git-идентичность.** В репозитории может остаться
   `user.name`/`user.email` агента; её нужно заменить глобальной
   идентичностью человека или удалить.
6. **`runuser` в root-скрипте.** Если скрипт уже работает от root,
   `runuser -u <user> --` заменяет вложенный `sudo -H -u` и не показывает
   sudo-лекцию. В ручных командах человек по-прежнему использует `sudo`.
7. **Для одного локального репо достаточно трёх команд.** Канонический
   инструмент нужен для повторяемых/переносимых случаев; для разовой
   передачи проще ACL → `chown` → `safe.directory`.

## Переход понимания

**Было:**

- one-shot копия — основной режим; reusable — альтернатива;
- `chown` до ACL; `setfacl` от человека;
- default ACL только для агента;
- `safe.directory` для обоих;
- вложенный `sudo` без документированной альтернативы.

**Стало:**

- reusable с `--target` — основной режим; one-shot — только для
  переносимой папки;
- ACL до `chown`; `setfacl` от root; при ошибке ACL владение не меняется;
- default ACL для агента и человека;
- `safe.directory` агенту; человеку не нужен;
- `runuser` задокументирован для root-скриптов;
- для одного локального репо — три команды, инструмент — для повторяемых
  случаев.
