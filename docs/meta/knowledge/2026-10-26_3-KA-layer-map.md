# Зачем нужна карта слоёв

## Исходная ситуация

Слои проекта были описаны в разных местах: KA, WI, trail, публичный журнал, private log, private track, tracks, локальная сессия. Новый участник или агент собирал структуру по кускам и мог:

- придумать папку `private/` вместо предусмотренного слоя;
- спутать WI-черновик с README хранилища trail;
- искать private log не там;
- задавать вопросы там, где структура уже была определена.

## Приобретённое понимание

1. Нужна одна карта: слой → путь → в git или приватно → назначение.
2. Карта — живой артефакт, но не источник понимания: она ссылается на KA и policy.
3. Карта снижает ошибки при создании, перемещении и передаче документов.
4. Карта помогает новым сессиям и агентам начинать с одного входа.
5. Если материал не укладывается в слой, карта заставляет остановиться и спросить, а не изобретать папку.

## Следствия

- Карта: `docs/meta/artefacts/layer-map.md`.
- Ссылки на карту добавлены в `AGENTS.md`, `README.md`.
- Карта фиксирует private track: `docs/tracks/private/log/` для лога и `docs/tracks/private/` для конвейера.
- Старый путь `docs/log/private/` считается устаревшим; миграция проектов — отдельно.
- Шаблон нового проекта и кит не меняются этой KA.

## Границы

Не решает: миграцию всех приватных логов, изменения шаблона/кита, автоматический линтер публичных ссылок на private.
