# Участие человека и агента в KA: автор, ведущий, степень участия

## Исходная ситуация

KA часто готовятся совместно: агент пишет, человек направляет, проверяет
или не открывает. Разделять KA на «сгенерированные ИИ» и «ручные» плохо:
критерий размывается, совместная работа не попадает ни в одну категорию,
а авторство не предсказывает качество.

При этом остаётся практическая нужда: во время осмысления надо видеть,
где человек действительно проверял, где только skim, а где не открывал.
Особенно если KA подготовлены конвейером.

## Приобретённое понимание

1. **Авторство и ответственность — разные вещи.** Текст может написать
   агент, а ведущим и ответственным быть человек. И наоборот.

2. **Степень участия человека — отдельная ось.** «Не открывал»,
   «посмотрел наскоро» и «выверил построчно» — это разные состояния,
   и они не выводятся из авторства.

3. **Основание — третья ось.** Извлечено из источников, наблюдение,
   синтез или решение — разный риск и разная цена проверки.

4. **Агент заполняет только то, что знает.** По умолчанию он пишет
   `composed_by: agent`, `lead: agent`, `human_participation: none`.
   Он не имеет права утверждать, что человек проверял.

5. **Человек сам правит свою степень участия.** Если посмотрел — ставит
   `skim`; если выверил — `line`; если переписал — `author`. Если берёт
   ответственность — меняет `lead` на `human`.

6. **Отсутствие полей — это `unknown`, а не «проверено».** Старые KA не
   переразмечаются догадками. Честное «неизвестно» лучше выдуманного
   `human`/`line`.

7. **Метаданные участия не меняют тело KA.** Обновляются только поля
   участия; утверждения и `scope_of_understanding` остаются read-only.
   Новое понимание — новый KA.

## Значения

Использовать только эти значения; не изобретать свои.

| Поле | Допустимые значения | Смысл |
| --- | --- | --- |
| `composed_by` | `agent` | текст составил агент |
| | `human` | текст составил человек |
| | `joint` | существенный текст с обеих сторон |
| `lead` | `agent` | за включение и судьбу KA отвечает агент |
| | `human` | ответственность взял человек |
| `human_participation` | `none` | человек не открывал после составления |
| | `skim` | посмотрел, общая оценка, без построчной проверки |
| | `line` | проверил утверждения/цитаты построчно |
| | `author` | писал или переписывал текст |
| `participation_updated` | дата `YYYY-MM-DD` | когда поля участия менялись |

Правила совместимости:

- `human_participation: author` требует `composed_by: human` или `joint`;
- `composed_by: agent` не запрещает `lead: human`: человек может взять
  ответственность, даже если текст писал агент;
- `human_participation: none` не запрещает `lead: human`, но это явный
  сигнал «отвечаю, но не проверял»;
- `lead: agent` при `human_participation: line` допустим: человек
  проверил, но ответственность оставил агенту — это тоже нужно видеть.

## Кто и когда меняет

Агент при создании KA:

```yaml
composed_by: agent          # agent | human | joint
lead: agent                 # agent | human
human_participation: none   # none | skim | line | author
participation_updated: 2026-10-26  # YYYY-MM-DD
```

Человек после осмысления (пример):

```yaml
composed_by: agent
lead: human
human_participation: line
participation_updated: 2026-10-27
```

Если KA составлен совместно, агент ставит `composed_by: joint`; степень
участия человека всё равно остаётся `none` до его собственной правки.

## Переход понимания

**Было:**

- разделение по автору: «ИИ» / «ручное»;
- участие человека не фиксировалось;
- прочитанный и непрочитанный KA выглядели одинаково.

**Стало:**

- `composed_by` — кто составил;
- `lead` — кто отвечает;
- `human_participation` — что человек реально сделал;
- `participation_updated` — когда это менялось;
- отсутствие полей = `unknown`, не «проверено».

## Где что живёт

- frontmatter KA — источник метаданных;
- этот KA — первый пример и словарь;
- шаблон KA и AGENTS — следующий шаг, отдельным изменением;
- производная очередь ревизии (по `human_participation`) — возможный
  следующий шаг, не обязательный для действия правила.

## Границы

- это self-reported metadata, а не доказательство проверки;
- одна степень на KA, не на каждое предложение; при смешении — дробить KA;
- не заменяет `performed_by` и `review_recommended` в блоке ревизии:
  `performed_by` — кто исполнял задачу, `composed_by` — кто составил KA;
- не требует автоматического backfill старых KA;
- не вводит разделения «ИИ/человек» в хранении или поиске.

## Что я не проверял

- массовую разметку старых KA;
- очередь ревизии по этим полям;
- несколько человек/агентов на один KA;
- конфликт `lead` и `human_participation` в спорных случаях;
- автоматическую валидацию значений.
