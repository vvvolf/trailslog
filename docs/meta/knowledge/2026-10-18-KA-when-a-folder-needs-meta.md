# Когда папке нужна meta, а когда readme

## Исходная ситуация

При создании каталога `prompts/` (команд для ИИ-ассистентов) возник вопрос:
достаточно ли в нём readme или нужна собственная meta. До этого вложенные
meta появлялись по мере необходимости, без явно сформулированного критерия.

## Приобретённое понимание

readme отвечает на вопрос «что это за папка и как ей пользоваться» — это
ориентация, одно текущее описание.

meta нужна, когда у папки появляется собственная история изменений
понимания: когда устройство самого механизма становится предметом развития,
а не только описания. Тогда требуются датированные документы, причины
решений, открытые вопросы.

Операционный тест: правила папки стали меняться сами — пора meta. Пока
меняется только содержимое при неизменных правилах — достаточно readme.

## Проверка на существующих случаях

- `work_item_trails/meta` — правила (спека Work Item) эволюционируют → meta;
- `log/meta`, `tracks/ideas/meta` — правила будут выкристаллизовываться
  из практики → meta с самого начала;
- `prompts/` — назначение стабильно, правила одни → readme достаточно.

## Изменение модели

В модель добавлено различие: readme — описание папки как она есть; meta —
сопровождение развития понимания о папке. readme и meta совместимы в одной
папке (прецедент: `work_item_trails/meta/readme.md`). Переход readme → meta
совершается в момент, когда предметом обсуждения становится устройство
самого механизма.

## Замечания генерации

Критерий сформулирован постфактум для уже существующих решений; его
состоятельность как руководства к действию будет проверяться дальнейшей
практикой.
