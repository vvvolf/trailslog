````md
Во время текущего обсуждения могла появиться самостоятельная единица дальнейшей работы.

Под самостоятельной единицей дальнейшей работы понимается законченный вопрос, идея, гипотеза, наблюдение, архитектурное решение или направление работы, к которому предполагается вернуться позднее.

Необходимо полностью сформировать готовый Markdown-документ Work Item.

Документ должен быть самодостаточным и пригодным для немедленного сохранения в файл без какого-либо дополнительного редактирования.

Весь результат должен представлять собой один Markdown-документ.

Используй следующий формат.

```md
---
work_item_scope: |
    ...

reason_for_capture: |
    ...

resume_context: |
    ...
---

# ...

## Contract

Документ построен по формату Work Item.

Основные принципы:

- один Work Item сопровождает одну самостоятельную единицу дальнейшей работы;
- `work_item_scope` определяет границы сопровождаемой единицы;
- `reason_for_capture` объясняет, почему именно этот материал следует сохранить как отдельный Work Item;
- `resume_context` позволяет восстановить состояние работы и естественно продолжить исследование;
- извлечённые реплики сохраняются без пересказа и редактирования.

# Правила формирования

## work_item_scope

Поле отвечает на вопрос:

> Какую самостоятельную единицу дальнейшей работы сопровождает данный документ?

Назначение поля — определить границы сопровождаемой единицы.

Не пересказывать обсуждение.

Не перечислять детали реализации.

После чтения поля должно быть понятно:

- что относится к данному Work Item;
- что сознательно в него не входит.

---

## reason_for_capture

Поле отвечает на вопрос:

> Почему данный материал следует сохранить как самостоятельный Work Item?

Поле описывает **ценность захвата материала**, а не происхождение идеи и не план дальнейшей работы.

При формировании текста желательно учитывать три независимых аспекта.

### 1. Почему этот материал нельзя потерять?

Следует объяснить, почему обсуждение обладает самостоятельной ценностью.

Например:

- содержит несколько взаимосвязанных идей;
- затрагивает важное направление исследования;
- объединяет материалы, требующие отдельной обработки;
- содержит архитектурные решения или наблюдения, которые сложно восстановить позднее.

### 2. Какие основные направления или темы делает возможной последующая обработка?

При необходимости допускается кратко перечислить наиболее существенные направления, возникшие в обсуждении.

Это не должен быть подробный перечень ожидаемых результатов.

Достаточно обозначить, какие самостоятельные темы содержит данный материал.

### 3. Общая ценность последующей обработки

При необходимости можно кратко указать, почему последующая работа над данным материалом представляется перспективной.

Например:

- ожидается выделение нескольких самостоятельных направлений;
- материал способен породить новые Knowledge;
- обсуждение содержит несколько потенциальных архитектурных решений.

Не следует превращать данный раздел в план работ или перечисление всех ожидаемых результатов.

Если отдельные аспекты несущественны, их можно не выделять явно.

Главная цель поля — объяснить, почему данный материал заслуживает самостоятельного сопровождения.

## resume_context

Поле предназначено для восстановления контекста в новом чате.

Оно должно позволить продолжить работу без повторного чтения полного документа.

Поле описывает текущее состояние понимания.

Не пересказывать диалог.

Желательно указать:

- что уже считается установленным;
- какие решения уже приняты;
- какие варианты уже отвергнуты;
- какие вопросы остаются открытыми;
- что наиболее естественно обсуждать следующим шагом.

Поле не должно объяснять происхождение Work Item и не должно описывать причины его сохранения.

---

## Имя файла

Предложить пять вариантов.

Формат:

YYYY-MM-DD Название.md

После этого выбрать один рекомендуемый вариант (его выделить **жирным**).

Для каждого имени указать короткий комментарий.

Комментарий к рекомендуемому варианту должен объяснять, почему именно он выбран основным.

---

## Извлечённые реплики

Самостоятельно определить естественную смысловую границу обсуждения.

Извлечь только относящиеся к данной единице сообщения.

Использовать формат:

> User:
> ...

> Assistant:
> ...

Не пересказывать.

Не редактировать.

Не менять порядок сообщений.

---

## Ограничение размера ответа

Если весь диапазон сообщений невозможно вывести полностью:

- вывести максимально возможный непрерывный диапазон;
- не пропускать сообщения внутри диапазона;
- после последней автоматически вставленной реплики добавить непосредственно в раздел «Извлечённые реплики»:

---

⚠ Автоматическое извлечение остановлено из-за ограничения размера ответа.

Документ содержит начало выбранной единицы обсуждения.

Продолжение необходимо добавить вручную.

Автоматически перенесено приблизительно: \<N> сообщений.

Предположительно осталось перенести: \<M> сообщений.

Проверь полноту документа вручную.

---

## Замечания генерации

Если во время формирования документа возникли ограничения, неоднозначности или сомнения (например, трудно определить естественную границу Work Item), описать их здесь.

Если замечаний нет — оставить раздел пустым.

---

Никакой текст не должен выводиться вне Markdown-документа.
````
